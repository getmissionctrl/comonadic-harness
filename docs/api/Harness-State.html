Harness.State

Description

The harness state S and the three quotients on it: project (lossy, what the model sees), the affordance fold, and view (the annotation placed on every tree node).

project :: S -> Prompt Source #

Quotient 1. Lossy, total, recomputed each turn.

allTools :: [ToolSpec] Source #

afford :: S -> [ToolSpec] Source #

Mode-dependent affordances — a fold over the transcript, not a constant. This is what makes the interface polynomial. commit is only offered once a write has happened.

request :: S -> Request Source #

In Summarising mode the request carries a summarisation instruction and no tools — so compaction goes through the same Render constructor.

view :: S -> Ctx Source #

renderLine :: Turn -> String Source #

Render one turn to a prompt line. Factored out so the prefix-stability law (§16.6) can be stated: in Working mode, project (t : ts) == project ts <> renderLine t (appending a turn appends to the end of the prompt, leaving the cached prefix untouched). [established]
